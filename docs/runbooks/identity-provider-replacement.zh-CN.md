# 更换身份提供方与解除旧绑定

只使用公开 OIDC 协议及 taboo 自有成员关系。禁止用 email、显示名或管理员填写的 sub 代替身份所有权证明。不需要重新加密、移动或重建组织、项目、秘密及其版本。

1. owner 登记新身份连接，运维将精确 issuer 加入允许列表；回调、Client、密钥和安全画像按提供方能力配置。迁移无需打开 JIT。先保留旧提供方可用。
2. 用户在原账号当前组织点击「登录身份」，选择新连接并确认更换。外部旧会话必须仍有效且满足其近期/强认证策略；本地账号必须再次提供密码及已启用的 TOTP（不接受恢复码代替这次迁移证明）。仅有旧 Bearer Token 不足以迁移。
3. 浏览器前往新提供方重新认证。服务端验证新代码、PKCE、state、nonce、Token 和新策略要求；5 分钟内一次性完成，旧会话/账号被停用、策略改变、成员移除或新身份已属其他账号均失败。失败不合并账号。
4. 原子更换 `(issuer, sub)`，保留 taboo user ID、角色和显式动作授权；解除旧身份绑定、清除旧本地密码/TOTP/恢复凭据、撤销旧会话与 Refresh Token，再建立新 BFF 会话。审计失败则全部回滚。新连接的默认角色不升级迁移用户。
5. 核对成员权限、项目/环境 ID、秘密版本和密文一致。原本地账号转为外部来源后，秘密动作遵循显式授权，旧 owner/write 权限不会自动复制为 reveal/export。owner 应先盘点并授权必要动作。
6. 每个组织分别核实新连接和成员入口，迁移需要保留至少一位可通过启用外部连接登录的 owner。确认后停用/删除旧连接；秘密和审计保留。其余组织的身份源与准入不会因为一次迁移而自动新建或调整。

当前采用替换并解绑旧身份，一个 taboo 用户保留一个外部身份；不是任意多账号聚合。pairwise sub 改变也必须走完整证明。若用户已先通过新提供方 JIT 建立另一账号，本流程拒绝自动合并；由组织 owner 核对其成员关系，不能直接覆盖已绑定的外部身份。

旧提供方完全不可用时不能跳过旧身份验证自助接管账号。使用另一个经过验证的组织 owner 恢复组织管理，再按运维恢复流程处理身份；不要编辑邮箱或猜测 sub 获得原权限。

回退同样需要在新会话下证明旧连接的身份，作为一次反向替换。不要用过期数据库快照覆盖迁移后业务写入。生产操作前保留数据库、配置和根材料的完整备份，按版本配套恢复。

公开验证：`go test -race ./internal/server -run 'TestFederation.*Replacement'`（SQLite 和 PostgreSQL），以及 `TABOO_TEST_BROWSER=1 ./scripts/test-federation.sh` 的真实 Keycloak 浏览器替换流程。
